# 技术设计与实现边界

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `app.py` | Streamlit 界面、登录、上传、临时文件处理、结果展示、Excel 导出 |
| `core.py` | 多模态模型调用、任务提示词、JSON 解析、结构化结果 |
| `knowledge.py` | 知识表加载、文本与编号归一、名称和别名匹配、近似匹配 |
| `script_checker.py` | OpenCC 香港繁体转换与字符差异比较 |
| `make_demo_data.py` | 生成独立的合成知识表，不分发客户资料 |
| `tests/test_offline.py` | 不调用外部服务的核心逻辑检查 |

## 模型与规则的分工

模型负责从图片提取成分、理解标签文字层次和给出繁体建议。知识表负责提供匹配条目的名称、编号、功能和备注；代码负责匹配顺序、结果分类及结构化导出。当前没有把查询结果回填给模型生成答案，也没有模型自主选择工具的循环。

## 知识结构

- `additives_master`：`additive_id`、简体／香港繁体／英文标准名称、E 编号、功能与备注。
- `additives_aliases`：别名、别名类型、关联的 `additive_id`、是否参加近似匹配。
- `common_non_additives`：普通配料名称及归一名称。

主表通过 `additive_id` 与别名关联。公开示例不包含任何真实客户知识记录，也不对知识覆盖度作承诺。

## 提示词设计

成分提取提示词限定处理配料区域，排除品牌、广告、营养表等内容，要求不得补充图片中不存在的成分，并输出 `ingredients` 数组。标签提示词要求按阅读顺序输出文本块，保留原始与建议字段，以支持差异展示。

这是提示词层面的约束，不是结果正确性的保证。程序会检查 JSON 是否可解析及结果是否非空；仍需加强类型、字段和业务语义校验。

## 已知限制

1. 成分提取会去掉部分剂量和括号说明；它适合当前名称查询任务，不适合作为完整法规判定的输入。
2. 近似匹配只选取一个候选，短名称及相似化学名称可能误匹配，应人工复核。
3. 模型产生的“原文”并非独立 OCR 真值；相同识别错误可能不会出现在差异中。
4. OpenCC 的转换差异标记与模型建议来自不同路径，两者结论可能不一致。
5. Streamlit 重运行可能重复触发识别；下一步应增加明确提交按钮与结果状态缓存。
6. 登录是单组账号密码的原型控制，不是企业 SSO、角色权限或审计体系。
7. 暂未实现模型调用重试策略、用量计量、集中日志及多人审批。

## 公开整理新增修正

- 缺少账号配置时拒绝登录，避免空账号与空密码匹配成功。
- 实例创建时读取模型配置，避免在 `.env` 加载前固定默认值。
- 清洗成分名时保留前导数字，避免破坏数字开头的名称。
- 将字符串 `False` 视为关闭近似匹配，而不是按非空字符串判真。

这些修正属于本次公开版本整理，不用于追述 2026 年 4 月原版已经通过的验证。
