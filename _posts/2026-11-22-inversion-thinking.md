<div class="seg">
<p class="en">Facing an important goal, / we usually ask: / “How do we make this succeed?” //</p>
<p class="zh" lang="zh-Hans">面对一个重要目标，我们习惯问：「怎样让它成功？」</p>
</div>

<div class="seg">
<p class="en">Inversion / turns the question around: / “What would make it fail?” //</p>
<p class="zh" lang="zh-Hans">逆向思维（Inversion）建议把问题翻过来：什么会让它失败？</p>
</div>

<div class="seg">
<p class="en">This is not / about creating anxiety. // The paths to success / are usually many, / while the fatal errors / tend to be fewer, / more concentrated / and easier to spot. // Instead of imagining / a perfect plan, / start by removing / the risks that could / break the whole thing. //</p>
<p class="zh" lang="zh-Hans">这不是为了制造焦虑，而是因为复杂目标的成功路径往往很多，致命错误却通常更集中、更容易识别。与其幻想一套完美方案，不如先排除那些足以让全局失效的风险。</p>
</div>

<h2>Why thinking backwards works better<span class="h-zh" lang="zh-Hans">为什么反着想更有效</span></h2>

<div class="seg">
<p class="en">The mathematician Jacobi / left a short piece of advice: / “Invert, always invert.” // Charlie Munger / applied the same habit / widely / to business, / investing / and life decisions. //</p>
<p class="zh" lang="zh-Hans">数学家雅可比留下过一句简短的方法论：「Invert, always invert.」查理·芒格则把逆向思考广泛用于商业、投资与人生决策。</p>
</div>

<div class="seg">
<p class="en">It works / for three main reasons. //</p>
<p class="zh" lang="zh-Hans">它有效，主要有三个原因。</p>
</div>

<div class="seg">
<p class="en">First, / avoiding big mistakes / is usually more achievable / than getting everything right. // A project needs / requirements, / data, / technology, / communication, / resources / and timing / to all line up. // To fail, / it may only need / one key assumption / to stay false / for a long time. //</p>
<p class="zh" lang="zh-Hans">第一，避免重大错误通常比做对所有事情更可行。一个项目要成功，需要需求、数据、技术、沟通、资源和时机共同配合；但要失败，可能只需要一个关键前提长期不成立。</p>
</div>

<div class="seg">
<p class="en">Second, / failure paths / expose the blind spots / of a positive plan. // When we discuss / only benefits / and ideal states, / optimism easily takes over. // Asking “how could this go bad” / forces us / to check / the constraints we ignored. //</p>
<p class="zh" lang="zh-Hans">第二，失败路径能暴露正向方案的盲点。当我们只讨论收益和理想状态，很容易受到乐观预期影响。反问「它怎样会变坏」，会迫使我们检查被忽略的约束。</p>
</div>

<div class="seg">
<p class="en">Third, / a lot of improvement / comes from subtraction. // Removing / one meaningless approval, / deleting / a duplicate data-entry step, / or naming / an interface nobody owns / often beats / adding another management action. //</p>
<p class="zh" lang="zh-Hans">第三，很多改进来自减法。减少一次无意义审批、删除一个重复录入环节、明确一个无人负责的接口，往往比再增加一套管理动作更有效。</p>
</div>

<h2>A three-step framework you can use today<span class="h-zh" lang="zh-Hans">一个可以直接使用的三步框架</span></h2>

<h3>Step 1. Write the goal concretely<span class="h-zh" lang="zh-Hans">第一步：把目标写具体</span></h3>

<div class="seg">
<p class="en">Do not write / “deliver a good project” / or “improve operations”. // Define a result / you can judge. // For example: / go live with the core process / on the agreed date, / let key users / work independently, / and do not interrupt / normal business. //</p>
<p class="zh" lang="zh-Hans">不要只写「做好项目」或「改善经营」，而要定义可判断的结果。例如：在约定时间内上线核心流程，关键用户能够独立完成操作，且上线不中断正常业务。</p>
</div>

<div class="seg">
<p class="en">The vaguer the goal, / the more / the risk discussion / drifts into generalities. //</p>
<p class="zh" lang="zh-Hans">目标越模糊，后面的风险讨论越容易变成泛泛而谈。</p>
</div>

<h3>Step 2. Assume it has already failed<span class="h-zh" lang="zh-Hans">第二步：假设它已经失败</span></h3>

<div class="seg">
<p class="en">This is the pre-mortem. // Before you act, / imagine you are / in the future / and the project has failed, / then ask: / “What most likely happened?” //</p>
<p class="zh" lang="zh-Hans">这就是 Pre-mortem（预演失败）：在行动开始前，假设时间已经来到未来，而项目已经失败，然后追问「最可能发生了什么」。</p>
</div>

<div class="seg">
<p class="en">For an enterprise system go-live, / common answers / might look like this. //</p>
<p class="zh" lang="zh-Hans">以企业系统上线为例，常见答案可能包括以下几点。</p>
</div>

<ul class="seg-list">
<li><span class="en">Scope kept changing, / so the team / could never freeze it. //</span><span class="zh" lang="zh-Hans">需求边界反复变化，团队始终无法冻结范围。</span></li>
<li><span class="en">Master data / was too weak, / so test results / did not represent real business. //</span><span class="zh" lang="zh-Hans">主数据质量不足，测试结果无法代表真实业务。</span></li>
<li><span class="en">Key users / did not give time, / so training and acceptance / became a formality. //</span><span class="zh" lang="zh-Hans">关键用户没有投入时间，培训与验收流于形式。</span></li>
<li><span class="en">Departments / used different definitions, / and nobody / could make the final call. //</span><span class="zh" lang="zh-Hans">跨部门口径不一致，问题无人最终拍板。</span></li>
<li><span class="en">Cutover / had no rollback plan, / so a small fault / became a business outage. //</span><span class="zh" lang="zh-Hans">上线切换缺少回退方案，小故障演变成业务中断。</span></li>
</ul>

<div class="seg">
<p class="en">This list / is more useful / than “let’s all pay attention to risk”, // because it points / at specific mechanisms. //</p>
<p class="zh" lang="zh-Hans">这张清单比「大家重视一下风险」更有用，因为它指向具体机制。</p>
</div>

<h3>Step 3. Put a guard on each failure path<span class="h-zh" lang="zh-Hans">第三步：给失败路径加上防线</span></h3>

<div class="seg">
<p class="en">Every major risk / should map / to one action / you can take in advance. //</p>
<p class="zh" lang="zh-Hans">每个重大风险都应该对应一个可以提前执行的动作。</p>
</div>

<div class="seg">
<p class="en">The output of inversion / is not “risk literature”. // It is / an owner, / a trigger condition / and a concrete action. //</p>
<p class="zh" lang="zh-Hans">逆向思考的产出不是一份「风险文学」，而是责任人、触发条件和具体动作。</p>
</div>

<h2>It also works for business and personal decisions<span class="h-zh" lang="zh-Hans">它也能用于商业与个人决策</span></h2>

<div class="seg">
<p class="en">In business analysis, / besides asking / “why might this company grow”, / ask: / what would keep / cash flow, / customer demand / or competitive advantage / getting worse? // These questions / move our attention / from the story / to the evidence. //</p>
<p class="zh" lang="zh-Hans">在商业分析中，除了问「这家公司为什么可能增长」，还可以问：什么因素会让现金流、客户需求或竞争优势持续恶化？这些问题能帮助我们把注意力从故事转向证据。</p>
</div>

<div class="seg">
<p class="en">In personal choices, / besides / “how do I get the ideal result”, / ask: / which habits / would almost certainly damage / long-term health, / reputation / or room to choose? // Some problems / do not need / a cleverer technique — / they need us / to stop / doing obviously harmful things / again and again. //</p>
<p class="zh" lang="zh-Hans">在个人选择中，除了问「怎样得到理想结果」，也可以问：哪些习惯几乎一定会损害长期健康、信誉或选择空间？有些问题不需要更聪明的技巧，只需要停止反复做明显有害的事。</p>
</div>

<h2>Three limits to keep in mind<span class="h-zh" lang="zh-Hans">三个使用边界</span></h2>

<ol class="seg-list">
<li><span class="en">Inversion / is not pessimism. // It serves action — / it does not prove / that nothing is worth doing. //</span><span class="zh" lang="zh-Hans">逆向思维不等于悲观。它服务于行动，不是证明什么都不值得做。</span></li>
<li><span class="en">Do not list risks / without measures. // If the list / changes no plan, / it is only emotional output. //</span><span class="zh" lang="zh-Hans">不能只列风险，不给措施。如果清单没有改变计划，它就只是情绪输出。</span></li>
<li><span class="en">It cannot replace / positive creation. // Avoiding errors / reduces loss / but does not create new value. // The usual order / is: / propose a plan first, / then use inversion / to check the holes. //</span><span class="zh" lang="zh-Hans">它不能替代正向创造。防错可以减少损失，却不会自动产生新价值。正确顺序通常是先提出方案，再用逆向思维检查漏洞。</span></li>
</ol>

<div class="seg">
<p class="en">For me, / the most practical line / is this. //</p>
<p class="zh" lang="zh-Hans">对我而言，这个模型最实用的一句话如下。</p>
</div>

<blockquote><div class="seg">
<p class="en">Do not only ask / how to succeed — / also ask / what would fail; // then cut off / the most fatal paths, / one by one. //</p>
<p class="zh" lang="zh-Hans">不只问怎样成功，也问什么会失败；然后把最致命的失败路径，一条条切断。</p>
</div></blockquote>
