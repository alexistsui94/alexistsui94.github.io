<div class="seg">
<p class="en">In his MIT lecture / How to Speak, / Patrick Winston / talks about presentation. // But the value / goes well beyond / a formal speech. // A project report, / a solution demo, / an interview defence / and everyday communication / all answer / the same question. //</p>
</div>

<blockquote><div class="seg">
<p class="en">How do you / make other people / really understand / what you mean? //</p>
</div></blockquote>

<div class="seg">
<p class="en">My biggest takeaway / is this: / a talk is not / pouring out / everything you know. // It is / designing a path / so the audience / can understand, / remember, / and judge / whether your claim is credible. //</p>
</div>

<h2>1. Open with a promise to the audience</h2>

<div class="seg">
<p class="en">Winston / does not recommend / opening with a joke. // When people / have just walked in, / they are not yet used / to your tone, / your background / or your way of speaking. // If a joke falls flat, / it only scatters attention. //</p>
</div>

<div class="seg">
<p class="en">A better opening / tells them / what they will take away. //</p>
</div>

<blockquote><div class="seg">
<p class="en">By the end of this talk, / you should be able to understand … //</p>
</div></blockquote>

<div class="seg">
<p class="en">This “enablement promise” / lets the audience know / why the next part / deserves their attention. //</p>
</div>

<h2>2. Never ask people to read and listen at once</h2>

<div class="seg">
<p class="en">It is hard / to process / two streams of language / at the same time. // If a slide / is full of text, / people read the screen / while listening to new content, / and both suffer. //</p>
</div>

<div class="seg">
<p class="en">So a slide / is not a script. // It is / a visual tool / that helps understanding. //</p>
</div>

<div class="seg">
<p class="en">You can check / each slide / with three questions. //</p>
</div>

<ul class="seg-list">
<li><span class="en">Does it serve / only one core idea? //</span></li>
<li><span class="en">Can the audience / see where to look / within a few seconds? //</span></li>
<li><span class="en">Even if the speaker / does not read it aloud, / is the slide still useful? //</span></li>
</ul>

<div class="seg">
<p class="en">Complex content / can be revealed / step by step, // so ideas appear / together with the reasoning — / instead of dumping / the whole answer / at once. //</p>
</div>

<h2>3. Let the core idea come back in cycles</h2>

<div class="seg">
<p class="en">Say an important point / once / and people may only hear it. // Say it again / from another angle / and they begin to understand. // Return to it / at the end / and they are more likely / to remember it. //</p>
</div>

<div class="seg">
<p class="en">This cycle / is not mechanical repetition. // It changes / the form of expression. //</p>
</div>

<blockquote><div class="seg">
<p class="en">State the idea / → explain with an example / → strengthen by contrast / → return to the idea at the end. //</p>
</div></blockquote>

<div class="seg">
<p class="en">The same / applies to project reports. // A key conclusion / can appear first, / be supported by facts, / cases / and risk analysis, / then come back / as a recommended action. //</p>
</div>

<h2>4. Leave signposts so people can re-enter</h2>

<div class="seg">
<p class="en">People / will drift off. // A good speaker / does not assume / constant attention, // but sets / “verbal punctuation” / on purpose. //</p>
</div>

<ul class="seg-list">
<li><span class="en">Where we are now. //</span></li>
<li><span class="en">What we just solved. //</span></li>
<li><span class="en">What we will discuss next. //</span></li>
<li><span class="en">Why this point matters. //</span></li>
</ul>

<div class="seg">
<p class="en">For example: //</p>
</div>

<blockquote><div class="seg">
<p class="en">So far, / we have finished / the first part. // This point matters / because … // Now I want / to turn to / the second issue. //</p>
</div></blockquote>

<div class="seg">
<p class="en">These sentences / look plain, / but they help people / find their place again — / so they do not / get completely lost / in what follows. //</p>
</div>

<h2>5. Use a fence and a near miss to show the contribution</h2>

<div class="seg">
<p class="en">Winston / talks about / a fence — / drawing a boundary / around your idea. // Which part / is background, / which part / is existing opinion, / which part / is your contribution, / and how your method / differs / from similar approaches. //</p>
</div>

<div class="seg">
<p class="en">Without a boundary, / it is hard for the audience / to see / what you actually added. //</p>
</div>

<div class="seg">
<p class="en">When explaining / an abstract standard, / you can also use / a near miss — / an example / that looks almost correct / but still has / a key flaw. //</p>
</div>

<blockquote><div class="seg">
<p class="en">A wrong example / → an almost-right / but flawed example / → a better example. //</p>
</div></blockquote>

<div class="seg">
<p class="en">Contrast / makes a standard concrete. // When presenting a solution, / instead of showing / only the final version, / also explain / why a version / that looked feasible / was still not good enough. //</p>
</div>

<h2>6. End on the contribution, not just a summary</h2>

<div class="seg">
<p class="en">“Today I covered three points” / is only / a replay of the agenda. // A better ending / answers: / what do people have now, / what can they see / that they could not see before, / and what did this talk / really contribute. //</p>
</div>

<blockquote><div class="seg">
<p class="en">If you remember / only one thing, / I hope it is this … //</p>
</div></blockquote>

<div class="seg">
<p class="en">Return / to the opening promise, / and the whole path / of understanding / is closed. //</p>
</div>

<h2>My practice checklist</h2>

<div class="seg">
<p class="en">Before my next report, / I will check / six things. //</p>
</div>

<ol class="seg-list">
<li><span class="en">Does the opening / say what the audience will gain? //</span></li>
<li><span class="en">Does each slide / carry only one core idea? //</span></li>
<li><span class="en">Does the key conclusion / return in different forms? //</span></li>
<li><span class="en">Are there clear signposts / between sections? //</span></li>
<li><span class="en">Do examples and contrast / explain my judgement? //</span></li>
<li><span class="en">Does the ending / return to the contribution / and the next action? //</span></li>
</ol>

<div class="seg">
<p class="en">Good expression / is not / moving information around. // It is / designing / attention / and the process / of understanding. //</p>
</div>
