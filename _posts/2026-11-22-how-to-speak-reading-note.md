<div class="seg">
<p class="en">In his MIT lecture / How to Speak, / Patrick Winston / talks about presentation. // But the value / goes well beyond / a formal speech. // A project report, / a solution demo, / an interview defence / and everyday communication / all answer / the same question. //</p>
<p class="zh" lang="zh-Hans">Patrick Winston 在 MIT 的《How to Speak》中谈表达，但这堂课的价值并不限于正式演讲。项目汇报、方案演示、求职答辩和日常沟通，都在回答同一个问题。</p>
</div>

<blockquote><div class="seg">
<p class="en">How do you / make other people / really understand / what you mean? //</p>
<p class="zh" lang="zh-Hans">怎样让别人真正理解你想表达的东西？</p>
</div></blockquote>

<div class="seg">
<p class="en">My biggest takeaway / is this: / a talk is not / pouring out / everything you know. // It is / designing a path / so the audience / can understand, / remember, / and judge / whether your claim is credible. //</p>
<p class="zh" lang="zh-Hans">我从中得到的最大启发是：演讲不是把自己知道的全部讲出来，而是设计一条路径，让听众能够理解、记住，并判断你的观点是否可信。</p>
</div>

<h2>1. Open with a promise to the audience<span class="h-zh" lang="zh-Hans">1. 开场先给听众一个承诺</span></h2>

<div class="seg">
<p class="en">Winston / does not recommend / opening with a joke. // When people / have just walked in, / they are not yet used / to your tone, / your background / or your way of speaking. // If a joke falls flat, / it only scatters attention. //</p>
<p class="zh" lang="zh-Hans">Winston 不建议一开始讲笑话。听众刚进入场地时，还没有适应你的语气、背景和表达方式，笑话一旦失效，反而分散注意力。</p>
</div>

<div class="seg">
<p class="en">A better opening / tells them / what they will take away. //</p>
<p class="zh" lang="zh-Hans">更好的开场是告诉大家：听完之后，他们会获得什么。</p>
</div>

<blockquote><div class="seg">
<p class="en">By the end of this talk, / you should be able to understand … //</p>
<p class="zh" lang="zh-Hans">今天这个报告结束后，大家应该能够理解……</p>
</div></blockquote>

<div class="seg">
<p class="en">This “enablement promise” / lets the audience know / why the next part / deserves their attention. //</p>
<p class="zh" lang="zh-Hans">这个「赋能式承诺」会让听众知道，接下来的内容为什么值得投入注意力。</p>
</div>

<h2>2. Never ask people to read and listen at once<span class="h-zh" lang="zh-Hans">2. 不要同时要求听众读和听</span></h2>

<div class="seg">
<p class="en">It is hard / to process / two streams of language / at the same time. // If a slide / is full of text, / people read the screen / while listening to new content, / and both suffer. //</p>
<p class="zh" lang="zh-Hans">人很难同时处理两路语言信息。如果幻灯片上放满文字，听众一边读屏幕，一边听你讲新的内容，两边都会受损。</p>
</div>

<div class="seg">
<p class="en">So a slide / is not a script. // It is / a visual tool / that helps understanding. //</p>
<p class="zh" lang="zh-Hans">因此，PPT 不是讲稿，而是帮助理解的视觉工具。</p>
</div>

<div class="seg">
<p class="en">You can check / each slide / with three questions. //</p>
<p class="zh" lang="zh-Hans">一页幻灯片可以用三个问题检查。</p>
</div>

<ul class="seg-list">
<li><span class="en">Does it serve / only one core idea? //</span><span class="zh" lang="zh-Hans">是否只服务一个核心观点？</span></li>
<li><span class="en">Can the audience / see where to look / within a few seconds? //</span><span class="zh" lang="zh-Hans">听众能否在几秒内知道应该看哪里？</span></li>
<li><span class="en">Even if the speaker / does not read it aloud, / is the slide still useful? //</span><span class="zh" lang="zh-Hans">即使演讲者不照读，这页是否仍然有帮助？</span></li>
</ul>

<div class="seg">
<p class="en">Complex content / can be revealed / step by step, // so ideas appear / together with the reasoning — / instead of dumping / the whole answer / at once. //</p>
<p class="zh" lang="zh-Hans">复杂内容可以逐步展开，让思想随着推理出现，而不是一次性把答案全部堆出来。</p>
</div>

<h2>3. Let the core idea come back in cycles<span class="h-zh" lang="zh-Hans">3. 核心观点需要循环出现</span></h2>

<div class="seg">
<p class="en">Say an important point / once / and people may only hear it. // Say it again / from another angle / and they begin to understand. // Return to it / at the end / and they are more likely / to remember it. //</p>
<p class="zh" lang="zh-Hans">重要观点只讲一次，听众可能只是听见；换一个角度再讲，才开始理解；在结尾重新回到它，才更可能记住。</p>
</div>

<div class="seg">
<p class="en">This cycle / is not mechanical repetition. // It changes / the form of expression. //</p>
<p class="zh" lang="zh-Hans">这种循环不是机械重复，而是改变表达形式。</p>
</div>

<blockquote><div class="seg">
<p class="en">State the idea / → explain with an example / → strengthen by contrast / → return to the idea at the end. //</p>
<p class="zh" lang="zh-Hans">提出观点 → 用例子解释 → 用对比强化 → 在结尾回到观点</p>
</div></blockquote>

<div class="seg">
<p class="en">The same / applies to project reports. // A key conclusion / can appear first, / be supported by facts, / cases / and risk analysis, / then come back / as a recommended action. //</p>
<p class="zh" lang="zh-Hans">项目汇报也适用。关键结论可以先出现，再通过事实、案例和风险分析支撑，最后回到建议行动。</p>
</div>

<h2>4. Leave signposts so people can re-enter<span class="h-zh" lang="zh-Hans">4. 给听众留下重新进入的路标</span></h2>

<div class="seg">
<p class="en">People / will drift off. // A good speaker / does not assume / constant attention, // but sets / “verbal punctuation” / on purpose. //</p>
<p class="zh" lang="zh-Hans">听众一定会走神。好的表达者不会假设所有人始终专注，而会主动设置「口头标点」。</p>
</div>

<ul class="seg-list">
<li><span class="en">Where we are now. //</span><span class="zh" lang="zh-Hans">现在讲到哪里。</span></li>
<li><span class="en">What we just solved. //</span><span class="zh" lang="zh-Hans">刚才解决了什么。</span></li>
<li><span class="en">What we will discuss next. //</span><span class="zh" lang="zh-Hans">接下来要讨论什么。</span></li>
<li><span class="en">Why this point matters. //</span><span class="zh" lang="zh-Hans">这一点为什么重要。</span></li>
</ul>

<div class="seg">
<p class="en">For example: //</p>
<p class="zh" lang="zh-Hans">例如：</p>
</div>

<blockquote><div class="seg">
<p class="en">So far, / we have finished / the first part. // This point matters / because … // Now I want / to turn to / the second issue. //</p>
<p class="zh" lang="zh-Hans">到这里，我们已经完成了第一部分。这一点很重要，因为……接下来我想讨论第二个问题。</p>
</div></blockquote>

<div class="seg">
<p class="en">These sentences / look plain, / but they help people / find their place again — / so they do not / get completely lost / in what follows. //</p>
<p class="zh" lang="zh-Hans">这些句子看似朴素，却能帮助听众重新定位，不至于在后面的内容里彻底迷路。</p>
</div>

<h2>5. Use a fence and a near miss to show the contribution<span class="h-zh" lang="zh-Hans">5. 用「围栏」和近失误例子讲清贡献</span></h2>

<div class="seg">
<p class="en">Winston / talks about / a fence — / drawing a boundary / around your idea. // Which part / is background, / which part / is existing opinion, / which part / is your contribution, / and how your method / differs / from similar approaches. //</p>
<p class="zh" lang="zh-Hans">Winston 提到 fence，也就是给观点画边界：哪些是背景知识，哪些是已有观点，哪些是你的贡献，你的方法与相近方案有什么不同。</p>
</div>

<div class="seg">
<p class="en">Without a boundary, / it is hard for the audience / to see / what you actually added. //</p>
<p class="zh" lang="zh-Hans">没有边界，听众很难判断你到底新增了什么。</p>
</div>

<div class="seg">
<p class="en">When explaining / an abstract standard, / you can also use / a near miss — / an example / that looks almost correct / but still has / a key flaw. //</p>
<p class="zh" lang="zh-Hans">解释抽象标准时，还可以使用 near miss —— 一个看起来接近正确、但仍有关键缺陷的例子。</p>
</div>

<blockquote><div class="seg">
<p class="en">A wrong example / → an almost-right / but flawed example / → a better example. //</p>
<p class="zh" lang="zh-Hans">错误例子 → 接近正确但有问题的例子 → 更好的例子</p>
</div></blockquote>

<div class="seg">
<p class="en">Contrast / makes a standard concrete. // When presenting a solution, / instead of showing / only the final version, / also explain / why a version / that looked feasible / was still not good enough. //</p>
<p class="zh" lang="zh-Hans">这种对比会让标准变得具体。讲方案时，与其只展示最终版本，不如同时说明为什么某个看似可行的版本仍然不够。</p>
</div>

<h2>6. End on the contribution, not just a summary<span class="h-zh" lang="zh-Hans">6. 结尾要回到贡献，而不只是总结</span></h2>

<div class="seg">
<p class="en">“Today I covered three points” / is only / a replay of the agenda. // A better ending / answers: / what do people have now, / what can they see / that they could not see before, / and what did this talk / really contribute. //</p>
<p class="zh" lang="zh-Hans">「今天我讲了三点」只是目录回放。更好的结尾应该回答：听众现在获得了什么，能够看见什么以前看不见的东西，这场分享真正贡献了什么。</p>
</div>

<blockquote><div class="seg">
<p class="en">If you remember / only one thing, / I hope it is this … //</p>
<p class="zh" lang="zh-Hans">如果只记住一点，我希望大家记住……</p>
</div></blockquote>

<div class="seg">
<p class="en">Return / to the opening promise, / and the whole path / of understanding / is closed. //</p>
<p class="zh" lang="zh-Hans">结尾回到开场的承诺，整条理解路径才算闭合。</p>
</div>

<h2>My practice checklist<span class="h-zh" lang="zh-Hans">我的实践清单</span></h2>

<div class="seg">
<p class="en">Before my next report, / I will check / six things. //</p>
<p class="zh" lang="zh-Hans">下一次准备汇报时，我会先检查六件事。</p>
</div>

<ol class="seg-list">
<li><span class="en">Does the opening / say what the audience will gain? //</span><span class="zh" lang="zh-Hans">开场是否明确说明听众会获得什么。</span></li>
<li><span class="en">Does each slide / carry only one core idea? //</span><span class="zh" lang="zh-Hans">每页 PPT 是否只有一个核心观点。</span></li>
<li><span class="en">Does the key conclusion / return in different forms? //</span><span class="zh" lang="zh-Hans">关键结论是否通过不同形式反复出现。</span></li>
<li><span class="en">Are there clear signposts / between sections? //</span><span class="zh" lang="zh-Hans">段落之间是否有清楚的路标。</span></li>
<li><span class="en">Do examples and contrast / explain my judgement? //</span><span class="zh" lang="zh-Hans">是否用例子和对比讲清自己的判断。</span></li>
<li><span class="en">Does the ending / return to the contribution / and the next action? //</span><span class="zh" lang="zh-Hans">结尾是否回到贡献与下一步行动。</span></li>
</ol>

<div class="seg">
<p class="en">Good expression / is not / moving information around. // It is / designing / attention / and the process / of understanding. //</p>
<p class="zh" lang="zh-Hans">好的表达不是信息的搬运，而是对注意力和理解过程的设计。</p>
</div>
